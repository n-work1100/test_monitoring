# Архітектурні рішення (ADR)

Контекст: задача `-51.0` з `read_user.txt` — «система моніторингу на основі SNMP для IP-камер і
мережевого обладнання, з Telegram, обов'язковим source of truth, Linux, можливо Docker».
Відповіді користувача `-51.1`: GitHub, безкоштовний варіант, камер немає (навчання),
SoT і Git-інтеграція — на мій розсуд.

---

## ADR-001 — Nagios Core, а не Zabbix

**Рішення:** Nagios Core 4.x у Docker.

**Причини:** вимога «безкоштовно» + попередній вибір користувача на користь Nagios.
Nagios Core безкоштовний без обмежень кількості об'єктів (Zabbix теж, але складніший стек:
server + DB + web + proxy, і більше «магії» в шаблонах).

**Наслідки:**
- конфігурація — текстові `.cfg` → ідеально лягає в Git (див. ADR-003);
- немає вбудованого LLD → автопошук портів робимо генератором/скриптом, а не UI;
- нотифікації в Telegram — власний скрипт (`tools/notify_telegram.sh`), ~40 рядків bash.

**Коли переглянути:** якщо об'єктів стане > 500–1000 або знадобиться складна кореляція
подій → Naemon/Mod-Gearman (drop-in) або Zabbix.

## ADR-002 — SNMPv2c (не v3)

**Рішення:** SNMPv2c із довгим read-only community, окремий сегмент мережі.

**Причини:** вимога користувача; більшість бюджетних камер і комутаторів v3 не підтримують.

**Наслідки / компенсація:**
- community ніколи не в Git (`.env` + `resource.cfg`, `chmod 600`);
- SNMP дозволений лише з IP моніторингу (лабораторно — мережа `172.30.0.0/24`);
- `gitleaks` у CI як запобіжник;
- шлях міграції: додати `_SNMP_VERSION` / v3-макроси в `inventory/hosts.yml` — генератор
  вже відокремлює «дані» від «конфігу».

## ADR-003 — Source of truth = Git, а не NetBox

**Рішення:** `inventory/hosts.yml` у репозиторії; NetBox — наступний етап.

**Причини:**
1. навчальний масштаб (2–10 об'єктів): NetBox — це +3 контейнери, +резервне копіювання,
   +API-синхронізація заради нуля користі;
2. Git уже дає те, що вимагалося від SoT: єдине джерело, історія, авторство, рев'ю, відкат;
3. PR у GitHub = безкоштовний «four-eyes» аудит зміни моніторингу.

**Наслідки:** зміна моніторингу = коміт. Немає UI-правок «на льоту» — це свідоме обмеження
(саме воно вбиває drift у моніторингу).

**Шлях міграції до NetBox (без переписування):** NetBox → `generator.py` → той самий
`inventory/hosts.yml` (або напряму в `nagios/etc/conf.d/generated/`). Схема полів
(`name/address/role/site/monitoring`) збігається з NetBox custom fields, тому міняється лише
джерело даних, а не шаблони Nagios.

## ADR-004 — «Git-інтеграція» = config-as-code + CI-гейт

**Рішення:** реалізовано варіант (A) з трьох можливих:
1. **(A) конфіг у Git** ← зроблено;
2. (B) моніторинг самих Git-сервісів — відкладено, у лабораторії немає Git-сервера;
3. (C) автостворення issue з інцидентів — відкладено (потрібен GitHub-токен із правами
   `issues: write`; для навчання надлишково).

**Обов'язкові гейти (реалізовано в `.github/workflows/ci.yml`):**
- `nagios -v` у контейнері → синтаксис і цілісність об'єктів;
- «генерація актуальна» → `git diff --exit-code` після `tools/gen.py`, щоб не було
  розбіжності «SoT vs задеплоєний конфіг»;
- `gitleaks` → community/токени не потрапляють в історію.

**Відкат:** `git revert` + `tools/deploy.sh`. Тег `prod-YYYY.MM.DD-N` на кожен деплой.

## ADR-005 — Docker Compose, один хост

**Рішення:** `docker compose` на Ubuntu VM; Nagios — контейнер `jasonrivers/nagios`.

**Причини:** відтворюваність (та сама команда на ноутбуці й на VM), ізоляція Nagios від
системних пакетів, легкий «знести й підняти заново».

**Наслідки:** стан (retention/status) живе в контейнері → історія втрачається при
перестворенні. Для навчання прийнятно; для проду — named volume або InfluxDB/Grafana.

## ADR-006 — Симулятори замість реальних камер

**Рішення:** `sim/snmpd` (комутатор) і `sim/camera` (snmpd + фейкові TCP 554/80).

**Причини:** камер немає (відповідь `-51.1`), а система має бути перевіреною end-to-end.

**Наслідки:** перевіряються реальні SNMP-запити (`sysUpTime`, `ifNumber`) і реальні TCP-порти,
тобто весь ланцюг «Nagios → пристрій → тригер → Telegram» тренується без обладнання.
Для реального обладнання достатньо змінити `address` у `inventory/hosts.yml`.
